# Portfolio project context

Personal portfolio of Nakulan T (AI Engineer, Chennai). Live root site: https://nakulant.github.io/portfolio/.
This is the **multi-mode** rebuild on branch `multi-mode` — not yet merged to `main` or deployed. Read this before changing anything.

## The big idea
The site has **one visitor-facing toggle** (bottom-right floating button, `ModeSwitcher`) that switches between
**four completely separate designs** — different layout components, typography, colour system, motion and a
distinct 3D scene each. Only two things are shared across all four:
- **Content**: `src/data.js` (profile, links, stats, work, principles, stack, timeline, projects) — the single
  source of truth. Never duplicate content into a mode file; import from `data.js`.
- **The XP/achievement layer**: `src/game.jsx` (`GameProvider`/`useGame`), mounted once in `App.jsx` above the
  mode router, so progress persists across mode switches. Currently only the RL mode's `Hud`/`Arena`/`Sections`
  read from it; the other three modes don't show XP UI (by design, for a calmer aesthetic) but the provider stays
  mounted so achievements/XP earned there aren't lost if the visitor switches back.

## The four modes (`src/mode.jsx` → `MODES`)
| id | Folder | Concept | 3D scene |
|---|---|---|---|

| `japanese` | `src/modes/japanese/` | Zen/washi aesthetic: Shippori Mincho + Noto Sans JP, vertical side labels, vermillion/ink/gold | `scene.js` — 3D torii gate over still water, falling sakura petals, glowing sun disc |

Each mode is a **full separate React component tree** (`<X>Site.jsx`) with its own CSS file imported at the top
of that component (Vite bundles all four CSS files statically; only one mode's DOM subtree is ever mounted).

## CSS isolation — read before touching any mode's CSS
All four stylesheets are always present in the bundle, so **every rule must be scoped** to avoid bleeding into
other modes:
- Tokens/component rules: scoped via `html[data-mode='X'] { ... }` (see `src/mode.jsx`, which sets
  `document.documentElement.dataset.mode`). `src/modes/rl/rl.css` was generated by programmatically wrapping the
  original single-mode stylesheet this way — every selector in it is prefixed `html[data-mode='rl'] ...`.
- **`@keyframes` are global by name, not scoped by nesting.** Each mode's keyframes must have unique names
  (RL uses an `rl-` prefix: `rl-blink`, `rl-pulse`, `rl-scan`, `rl-joint`, `rl-draw`, `rl-dots`, `rl-glitch`,
  `rl-toastin`, `rl-slidein`; Gaming uses `game-` prefix). If you add a keyframe to any mode, prefix it.
- `src/modes/base.css`: the only truly global stylesheet — box-sizing reset, `.mode-switcher` (deliberately does
  NOT use any mode's CSS variables, so it reads clearly over all four backgrounds), and `.scene3d-bg` (shared by
  the three non-RL 3D scenes).

## 3D scenes
- `src/three/useThreeScene.js`: shared hook — renderer lifecycle, resize (ResizeObserver), pause when off-screen
  (IntersectionObserver) or `prefers-reduced-motion`, a `pointer` parallax value, and a `readVar()` helper that
  re-reads CSS custom properties (so scenes re-colour on theme/mode change via a `MutationObserver` on
  `data-theme`/`data-mode`). `build({T, scene, camera, pointer, readVar, renderer, el})` returns
  `{ update(dt,t), onTheme(), resize(w,h), dispose() }`.
- `src/three/SceneCanvas.jsx`: thin wrapper — `<SceneCanvas build={...} className="jp-scene" label="…" />`.
- Three.js is dynamically imported inside the hook (`await import('three')`), so it code-splits into its own
  chunk and doesn't bloat the main bundle (~192KB gzip in its own chunk, loaded once any 3D scene mounts).
- RL's `Arena.jsx` predates this hook and has its own bespoke Three.js setup (OrbitControls, raycasting for
  click-to-edit, InstancedMesh tiles/arrows) — it's intentionally not migrated to `useThreeScene`, since it needs
  much more than a passive background (user interaction, `rl.js`/`game.jsx` wiring).

## Gotchas already hit and fixed once — don't reintroduce them
1. **Scroll position carries across mode switches** (React just swaps the tree in place). `mode.jsx`'s
   `ModeProvider` calls `window.scrollTo({top:0})` on every mode change after the first mount — if you refactor
   mode switching, keep this, or visitors land mid-page in the new mode instead of at its hero.
2. **RL's `.reveal` elements start at `opacity:0`** (scroll-reveal) and the achievement `data-section` tracking
   both depend on `IntersectionObserver` effects that used to live in the old single-mode `App.jsx`. They now
   live in `RLSite.jsx` itself (mount-time `useEffect`s) — if you move Hero/Sections around, keep those two
   effects attached to whatever mounts RL's DOM, or the hero content stays invisible forever.
3. Hermes fonts (Rules, Rules Gothic, Aeonik Fono) from the earlier `hermes-theme` branch are licensed — never
   copy them. This rebuild doesn't reference that branch at all.

## Stack and commands
- React 18 + Vite 5, plain CSS (no UI library), Three.js (dynamic import). Deployed to GitHub Pages via `gh-pages`.
- `npm run dev` / `npm run build` / `npm run deploy` (deploys `dist/` to the `gh-pages` branch root — **do not
  run this from `multi-mode` until it's reviewed and merged**, it replaces the live site).
- `vite.config.js`: `base` is `VITE_BASE` env var or `/portfolio/`.
